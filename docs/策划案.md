# 嘉豪的终端（E-Boy's Terminal）策划案

> 工业时代 2 附属模组 · 大方向文档  
> 本文只约定「做什么样的体验」，不展开功能清单与实现步骤。

---

## 1. 一句话定位

**在工业时代 2 的工厂里放一台（或一组）可编程终端，用代码读写产线状态、下发指令，把已经铺好的设备网络变成「可编排的自动化系统」。**

玩家扮演的不是「再造一套工业」，而是**在 IE2 现有产线之上写控制逻辑**——更接近 Minecraft 里 ComputerCraft 遇见 Create / 科技模组时的那种感觉，而不是另起一个独立工业包。

---

## 2. 参考调研（Minecraft 同类体验）

下列模组不代表要照搬机制，而是提炼**已被玩家验证过的乐趣**。

### 2.1 ComputerCraft / CC: Tweaked

- **基调**：上手快、一块「电脑」就能跑 Lua，通过**外设（Peripheral）**摸红石、箱子、机器。
- **乐趣**：写脚本 → 立刻看到世界变化；海龟机器人把「程序」和「物理动作」绑在一起。
- **可借鉴**：终端 + 侧向连接设备、清晰的 API 面、程序持久化与开机自启；**编程是手段，自动化是回报**。
- 参考：[CC: Tweaked 官网](https://www.tweaked.cc/)、[ComputerCraft Wiki](https://www.computercraft.info/wiki/Main_Page)

### 2.2 OpenComputers

- **基调**：**模块化装机**（CPU、内存、扩展卡），偏生存节奏；用 **Adapter** 对接大量科技模组。
- **乐趣**：给不同任务配不同配置的机器；电脑/机器人在存档间**状态延续**；用 Lua 做「工控机」而非魔法方块。
- **可借鉴**：与主工业模组的**接口层**思维（读库存、读进度、写开关），以及「先造得起终端，再谈写程序」的进度曲线。
- 参考：[OpenComputers 文档](https://ocdoc.cil.li/)、[MC百科 OC 条目](https://www.mcmod.cn/class/389.html)

### 2.3 Create × ComputerCraft（及 CC:C Bridge）

- **基调**：机械产线（转速、应力、序列传动、物流）**本身很复杂**，电脑负责**监视与编排**。
- **乐趣**：读 Speedometer / Stressometer、控制 Sequenced Gearshift、按条件向物流网络**下单要料**——程序是产线的「大脑」，Create 是「肌肉」。
- **可借鉴**：**不替代**传送带/合成/物流，只做**读状态 + 发命令**；显示器、仪表、地址化物流等「工控室」氛围。
- 参考：[Create 官方 CC 集成说明](https://github.com/Creators-of-Create/Create/wiki/ComputerCraft-Integration)、[CC:C Bridge](https://github.com/tweaked-programs/cccbridge)

### 2.4 Integrated Dynamics（对照组）

- **基调**：用逻辑网络、变量卡、Reader/Writer 做**可视化逻辑编程**，而非文本代码。
- **启示**：玩家要的是「**可组合的控制逻辑**」，文本脚本只是其中一种载体；IE2 已有电路、分拣、流体接口时，终端侧应**复用这些语义**，避免再造一套平行的「假红石」。

### 2.5 共性结论（本模组的玩法基调）

| 维度 | 取向 |
| --- | --- |
| 玩家身份 | 工厂里的**自控工程师**，不是纯建筑师 |
| 核心循环 | 观察产线 → 写/改程序 → 部署到终端 → 产线按逻辑运转 |
| 与工业模组关系 | **依附** IE2 设备与网络（电、机械、流体、物流、电路），不重复造机器 |
| 难度曲线 | 先「连上一台设备、读一个数、开一个关」，再谈多机协同与调度 |
| 表达手段 | 以**文本编程**为主（具体语言后续定），接口风格向「外设/API」靠拢 |
| 氛围 | 车间里的终端、仪表、日志——**工控 / 编程台**，而非奇幻魔法电脑 |

## 3. 在工业时代 2 中的位置

- **依赖关系**：无 IE2 则无法构成完整体验；本模组提供「控制层」，IE2 提供「执行层」。
- **不抢戏**：方块、配方、产线工艺仍归 IE2；嘉豪的终端只增加**可编程的控制与监视能力**。
- **自然衔接点**（方向性，非承诺列表）：与 VoltNet / 机械轴、流体网络、分拣与插入、仓储、电路信号等 IE2 已有子系统做**稳定、可文档化的 API**，让玩家用同一套终端语言指挥多种设备。

---

## 4. 设计原则（大方向约束）

1. **代码控制现场，不控制菜单**  
   成就感来自产线上的真实反馈（储量、转速、堵塞、缺料），而不是仅在 UI 里改数字。

2. **渐进式开放**  
   早期：单台设备、少量 API；后期：组网、事件、定时、多终端协作。避免一上来就要求玩家写操作系统。

3. **失败可诊断**  
   程序跑挂了，产线应有可观察现象（停机、告警、日志）；对齐 OC/CC 社区「调试脚本」的习惯，而不是静默失败。

4. **多人与存档友好**  
   终端程序与绑定关系应能随世界存档走；是否允许玩家间共享脚本库可作为后续社交/创意方向，初版不展开。

5. **附属模组边界**  
   不改动 IE2 核心平衡的大包大揽；优先用**扩展、适配器、新方块**交付，保持 IE2 本体可独立游玩。

---

## 5. 有意不做的事（防止方向漂移）

- **不做**第二套完整工业科技树或替代 IE2 的自动化方案。  
- **不做**纯解谜小游戏式「电脑」，与工厂现场脱节。  
- **不做**一上来就对标 OpenComputers 全模块装机 + 机器人 + 全息 UI 的大而全；先守住「**终端操控产线**」这一主轴。  
- **不默认**全员都是程序员；文档、示例工程、模板程序是体验的一部分（实现阶段再定）。

---

## 6. 体验愿景（玩家故事）

中期愿景可以这样描述：

> 高炉一线缺焦炭时，控制室终端里的脚本已经根据仓库存量降低了鼓风频率，并向备料站发出配送请求；  
> 玩家走过去，在终端屏幕上看到过去一小时的趋势曲线，改两行参数，保存，产线在新逻辑下继续跑——**工厂还是那座工厂，但大脑换成了自己写的。**

这就是「我的世界式：用电脑编程操作工业产线」在 SC + 工业时代 2 语境下的目标质感。
